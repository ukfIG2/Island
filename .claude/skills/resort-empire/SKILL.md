# Resort Empire — project conventions

Mobile **landscape** resort tycoon (Unity 6, URP). Guests arrive in waves, the player moves Workers between buildings to clear bottlenecks, gets a star rating, upgrades, and the next wave is bigger. Calm game: no stress, no punishment.

## Sources of truth

- Specs (Slovak) are in `Assets/Documentation/Specs/`. The **build document** (`build-document-prototype-mvp.pdf`) wins on mechanics and numbers. Its §4.8 table holds the tuning values. The UI handoff (`ui-screens-handoff.pdf`) wins on screens S1–S9.
- Backlog: `Assets/Documentation/jira_backlog_2026.10.07.ods` is the committed sprint plan. The Product Backlog `.xlsx` uses a **different FR numbering** (FR-001…064 vs Jira FR-01…69) — never mix them.
- Status: `Assets/Documentation/STATUS.md` — done / planned / gaps. Update §4 at the end of every working session.

## Architecture

| Layer | Folder | Rule |
|---|---|---|
| Simulation | `Assets/Scripts/Sim/` (asmdef `ResortEmpire.Sim`, `noEngineReferences: true`) | Pure C#, deterministic, no randomness, no UnityEngine. Authoritative for all game state. |
| Tests | `Assets/Scripts/Sim/Tests/` | NUnit EditMode. Every hard rule below has a test; keep them green. |
| Game flow | `Assets/Scripts/Game/` (`GameController`, `SaveSystem`, `GameBootstrap`) | `GameController` is the only owner of flow and player actions. |
| 3D view | `Assets/Scripts/Game/View/` | Reads sim state and reconciles visuals; **never mutates sim state**. |
| UI | `Assets/Scripts/Game/Ui/` | uGUI built in code; subscribes to `GameController` events. |

All gameplay tuning numbers (anything the economist would balance) live in `TuningConfig` — never hard-code them in sim, view or UI. Pure presentation values (animation timings, how many figures walk away after a wave, layout sizes) may stay in view/UI code as named constants.

## Hard rules (break none)

- Wave phases: `AwaitingWave → WaveIncoming → WaveActive → WaveResolving → WaveComplete`, plus pause. The word *i-d-l-e* is banned everywhere (code, comments, strings, docs) — the calm state is **AwaitingWave**.
- The wave timer closes **arrivals**, never the wave; a wave ends only when every queue is empty (WR3). Guests never leave mid-wave.
- **Never show a live satisfaction number during a wave.** Signals are queues, statuses and warnings; the number appears only on Wave Complete.
- Moving a Worker is always free, instant and needs no confirmation (WR5). Workers = buildings − 1, one slot per building.
- Upgrades and unlocks happen **only between waves** — during a wave the UI does not even show the button (WR6).
- Energy is an optional boost, never a gate: 5★ / Perfect must be reachable without it (WR8).
- Locked needs never spawn (WR9). Passive play must not reach 5★ from wave 3 on, except debut waves 4 and 7 (WR7).
- Calm tone: no countdowns, no "you lost" wording, one main button per screen.

## Unity constraints

- **New Input System only** (`activeInputHandler = 1`): `UnityEngine.InputSystem` for pointers, `InputSystemUIInputModule` for uGUI. Never `StandaloneInputModule` or the old `Input` class.
- UI text: legacy `Text` with `Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")`. No TextMeshPro.
- Materials: `Shader.Find("Universal Render Pipeline/Lit")`, color via `_BaseColor`.
- Prototype is a **3D blockout**: primitives built in code, no prefabs, no hand-edited scene content. Keep building visuals swappable so real art can drop in later.
- Canvas reference resolution 1920×1080, landscape only; the side panel must never cover the whole island.

## Workflow with the Unity MCP

1. Load the `unity-mcp-skill` skill before driving the editor.
2. After editing scripts: wait until `mcpforunity://editor/state` reports not compiling, then `read_console` for errors. Fix all errors before anything else.
3. Run tests: `run_tests(mode="EditMode")`, then poll `get_test_job`.
4. The game scene is generated by the menu item **Resort Empire → Create Game Scene** (`Assets/Scenes/GameScene.unity`). Verify visuals in play mode with `manage_camera(action="screenshot", include_image=True, max_resolution=512)`.
5. If the MCP endpoint fails: check whether the `pts-web-project` Docker container is holding port 8080.

## Git

The project uses **Git Flow** (decided by Ivan, 2026-10-26):

- `main` holds released versions only, one tagged release per sprint (`v0.1.0` = Sprint 1). Nobody commits to it directly.
- `develop` is the integration branch, created from `main`.
- `feature/CAM-<key>-<short-name>` is one branch per Jira issue, from `develop`. Ivan merges it back into `develop` himself with `git merge --no-ff`; the team uses no pull requests.
- `release/<version>` is cut from `develop` at sprint end; it only gets the version number, the `CHANGELOG.md` entry and release fixes, then merges into `main` (tagged `v<version>`) and back into `develop`.
- `hotfix/<version>` comes from `main` for urgent fixes only and merges into both `main` and `develop`.
- Commit messages start with the Jira key: `CAM-23 Add wave state machine with arrivals, seats and queues`.
- Every commit carries its real author and real time; teammates commit their own work from their own accounts.
- `dev-beta` is local only and never pushed: it holds the full prototype + MVP build, and later sprints take their code from it feature by feature.
- Push to GitHub (`origin` = `ukfIG2/Island`, private) **only when the user asks**.
- Don't commit generated folders (`Library/`, `Temp/`, `Logs/`, `UserSettings/` — already in `.gitignore`).
